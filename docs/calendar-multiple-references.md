# Protected multiple-event references

One original all-day Google event can also reference several disjoint MGF date slices. Sharing requires the same verified original booking ID in each slice and full Google coverage; overlapping slices, native bookings and unmatched IDs cannot share. Current source evidence is checked for previously saved links. This handles legacy partial-area changes across a single estate event without modifying either calendar's reservations.

One projected MGF occurrence can reference multiple existing Google area events. Store the full ID-to-event-hash set locally alongside the booking/source evidence hash. Old single-event links remain readable. Estate references are not ownership and never authorise PATCH, PUT or DELETE. From 3.36.0 a separate opt-in guarded PATCH worker can manage MGF-created events only; see `calendar-managed-lifecycle.md`. All linked estate events appear in the linked view; any missing or changed member blocks/requires review rather than recreating it. Acknowledging differences must retain the entire set.

Suggestions traverse verified WPBC import and consolidation lineage, retaining original area/date references. The legacy description's trailing Additional Information booking number is read locally, never exported; phone digits and arbitrary numbers are not identifiers. Only unique original IDs with matching dates/time/coverage qualify as recommendations. Differences and ambiguity remain for explicit review. Imported bookings without overlaps also remain blocked, rather than being guessed missing and duplicated. Native approved bookings without overlaps remain eligible for add-only sync; pending excluded unless separately configured.

Calendar Sync checkboxes save multiple references per reservation, unchecked by default. Existing events, descriptions, colours and sharing stay unchanged. Changing/cancelling a linked booking surfaces review; it does not change the master estate calendar.

MCP parity: administrator save_settings accepts calendar_sync with operation preview, reconcile or enable. Preview returns a fingerprint and redacted candidates (IDs, original reference, public summary/location/time), recommendations and link IDs, not descriptions/contact details/tokens. Writes require confirm=true and the fresh fingerprint; choices maps preview operation hashes to arrays of protect:GOOGLE_ID. Duplicate cross-booking assignment and stale choices fail closed. Reconcile saves references only and pauses; enable adds missing eligible native bookings and enables the existing five-minute worker. Both paths use the same lock, full snapshots and per-write source/Google revalidation as GUI. Never blindly retry an ambiguous insertion: refresh/read stable IDs first.
